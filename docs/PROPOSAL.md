# 기획서 초안: 탐라 데이터 비서

> 대회 기획서 양식이 따로 있으면 그 목차에 맞춰 옮겨 쓰세요. `[ ]` 부분은 실제 데이터를 정한 뒤 채웁니다.

## 1. 분석 주제와 필요성 (주제 타당성·창의성)
- **주제**: 제주 소상공인과 주민이 공공데이터로 "내 동네 상권과 관광 소비"를 직접 분석하는 AI 데이터 비서
- **문제**: 제주빅데이터센터·제주데이터허브에 카드 소비, 유동인구, 관광객 데이터가 공개되어 있지만,
  데이터를 내려받아 정리하고 집계·시각화하려면 엑셀 고급 기능이나 프로그래밍이 필요해 도민이 활용하기 어렵습니다.
- **해결**: 평소 말투로 질문하면 AI 에이전트가 데이터 탐색 → 집계 → 통계 → 시각화 → 해설까지 자동으로 수행합니다.
- **대상 사용자와 시나리오**
  - 애월읍 카페 예비 창업자: "관광객 카페 소비가 많은 요일과 달은?"
  - 읍면동 주민센터 담당자: "우리 동 관광객 소비가 작년보다 늘었나?"
  - 관광업 종사자: "외국인 관광객이 많이 쓰는 업종과 지역은?"

## 2. 활용 데이터 (필수 데이터 활용 적절성)
| 데이터 | 출처 | 활용 방법 |
|---|---|---|
| [예: 제주 카드 이용 현황] | [제주빅데이터센터] | 읍면동·업종·이용자별 소비 규모와 추이 |
| [예: 제주 관광객 소비/유동인구] | [제주데이터허브] | 관광 수요의 계절·요일 패턴 |
| [예: 기상 데이터] | [기상청 등, 선택] | 날씨와 관광 수요의 관계 |

- 데이터 설명을 `data/catalog.yaml`에 정리해 에이전트가 컬럼 의미를 정확히 이해하도록 합니다.

## 3. AI Agent 설계 (기술성·완성도)
- **모델**: Claude(claude-opus-5-5), adaptive thinking, 도구 호출(tool use) 기반 에이전트 루프
- **도구**
  1. `list_datasets`: 사용 가능한 데이터 목록
  2. `describe_dataset`: 컬럼 타입·결측·대표값 프로파일
  3. `run_sql`: DuckDB 읽기 전용 SQL (외부 파일 접근 차단)
  4. `run_python`: pandas 통계 계산, plotly 차트
- **절차**: 질문 이해 → 데이터 탐색 → 분석 → 자체 검증(오류 시 스스로 수정) → 정해진 형식의 보고서
- **환각 방지**: 모든 수치는 도구 실행 결과에서만 인용, 외부 사실 사용 금지, 가상 데이터 사용 시 명시
- **공공데이터 대응**: CP949/EUC-KR 자동 인식, 한글 파일·컬럼 이름 그대로 SQL 사용

## 4. 편의성·실용성
- 설치 없이 `run.bat`/`run.sh` 더블클릭으로 실행, 웹 화면에서 파일 업로드와 질문
- 예시 질문 버튼, 진행 단계 실시간 표시, 쉬운 용어 해설
- 결론 → 근거 → 활용 제안 → 주의점 → 후속 질문 순서의 일관된 답변
- HTML 보고서 내려받기로 회의·보고에 바로 활용

## 5. 결과 신뢰성·재현성
- 화면과 보고서 부록에 실행한 SQL·코드 전체 공개
- `runs/` 폴더에 실행 기록(JSON) 저장 → 같은 데이터로 같은 수치 재계산 가능
- 자동 테스트(pytest)로 데이터 적재·SQL 안전장치·에이전트 루프 검증
- [실제 데이터로 분석한 사례 2~3개와 수치를 SQL로 교차 확인한 결과를 첨부]

## 6. 기대 효과와 확장
- 도민의 데이터 활용 장벽을 낮춰 창업·상권 판단, 행정 의사결정에 공공데이터 활용 확대
- 새 데이터는 파일만 추가하면 바로 분석 가능 → 교통, 환경, 인구 등 다른 분야로 확장
